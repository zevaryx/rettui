# Changelog

What changed in each release of rettui. Releases before v1.6.0 are described on the [releases page](https://github.com/zevaryx/rettui/releases).

## v1.11.0

Changes since v1.10.0: pages to browse the repositories you host, with their files' syntax coloured, backups sealed with a passphrase (with a tool that opens them without rettui), files received with rncp and got from an rncp listener, interfaces others make known (found by interface discovery or sent in Sideband's telemetry) listed, mapped and added, asking where someone is from the map, a running sync stopped, page scripts that find Python and can run longer, identified visitors counted, Python in the Docker image, a desktop app that keeps running in the tray, colours and art written in Micron in RRC rooms, an Android app that follows the web UI's theme, stacks messages in its notifications, takes photos for messages, says when notifications are off, keeps the identity off new phones set up from it and makes backups on a schedule, rsReticulum and rsLXMF 1.4, a NomadNet node of rettui's own in place of rsNomad, and rettui under the Reticulum License.

### Added
- **Android notifications read as chats, and photos from the camera:** a conversation's or room's notification now shows its messages one under another (up to the last 8), with who said each, rather than only the newest; in a room it's titled with the room. Attaching a file (+ in a conversation, and other file pickers) offers the camera beside the files: a photo taken goes into the message, not the phone's gallery. See [Android](https://github.com/zevaryx/rettui/wiki/Android).
- **Android says when notifications are off:** with rettui's notifications (or its Messages ones) turned off, the app says once that messages and mentions arrive unannounced while it's closed, with **Turn them on**, which opens the right page of Android's settings. It asks again only after they've been on. The app also takes part in Android 13's predictive back. See [Android](https://github.com/zevaryx/rettui/wiki/Android).
- **Pages for the repositories you host:** the rngit node you host now serves NomadNet pages to browse them, as stock rngit's `serve_nomadnet` does, at the paths and with the page variables stock uses, so links work between the two. They list its groups and repositories, and for each its clone command, files, README (formatted), history, commits with the files they changed, and branches and tags. Source files have their lines numbered and their syntax coloured, for 28 languages and formats; Markdown and Micron files are shown formatted. Each visitor sees only what they may clone. `b` in the list of what's hosted (**Pages** in the web UI) opens them in the Browser, and the Repos tab opens your own node's pages without asking where they are. *rngit pages* (Settings › Hosting, on) turns them off. See [Hosting a Node](https://github.com/zevaryx/rettui/wiki/Hosting-a-Node#rngit-repositories).
- **Backups sealed with a passphrase:** backing up asks for a passphrase to seal the backup with, which you can leave empty: `B` in the terminal UI (typed twice, shown as dots), `rettui backup` in a terminal, **Download a backup** in the web UI, and *Save a full backup* in the Android app. A sealed backup can't be read or restored without it; `rettui restore` and the app ask for it. `rettui backup-key` turns a passphrase into a key that seals backups without the passphrase (`rettui backup --key`), which the Android app's scheduled backups use: turning them on asks for a passphrase first, and the phone keeps only the key. The passphrase is stretched with Argon2id, and the backup encrypted with X25519 and AES-256-GCM; a short passphrase, or a PIN, gets a warning. `rettui unseal` opens a sealed backup without restoring it or running rettui (the plain backup, or with `--identity` only the identity, to move to Sideband, NomadNet or another rettui), and `tools/unseal_backup.py` does the same with Python, without rettui. See [Sealed Backups](https://github.com/zevaryx/rettui/wiki/Sealed-Backups).
- **Backups on a schedule on Android:** *Identity and backups* can make a full backup every day or every week, while the phone charges, in a folder you choose with Android's folder picker. It keeps the newest 5 it made there, and deletes older ones, never other files. **Make one now** makes one straight away. A backup that fails says so in a notification, and the screen shows how the last one went. The backups hold the identity, so keep the folder private. See [Android](https://github.com/zevaryx/rettui/wiki/Android#identity-and-backups).
- **Desktop app keeps running when closed:** in the desktop app (`rettui-desktop`), closing the window leaves rettui running in the background, so messages keep arriving and notifications keep coming, with an icon in the system tray (the menu bar on a Mac) to open it again or quit. *Keep running when closed* (Settings › System, `keep_running`, on) turns that off, and *Minimize to tray* (`minimize_to_tray`, off) hides the window to the tray when it's minimized. Starting the app again while it runs opens its window, rather than starting a second rettui. On Linux the tray needs libayatana-appindicator; without it the window closes as before. The Flatpak no longer closes a second after it opens: it's now built on the GNOME 51 runtime, as the WebKit in GNOME 48's had the system kill it. See [Development](https://github.com/zevaryx/rettui/wiki/Development).
- **Page scripts find Python, and can take longer:** *Script PATH* (Settings, Hosting; terminal only) sets the `PATH` visitors' scripts run with: folders joined with colons, or `host` for rettui's own, as NomadNet does, so `#!/usr/bin/env python3` works with Homebrew, pyenv or a virtual environment. *Script time limit* (1 to 120 seconds, 10 by default) says how long a script may run. Your own view of a script page uses the same values. See [Hosting a Node](https://github.com/zevaryx/rettui/wiki/Hosting-a-Node#script-pages).
- **Receive files with rncp:** *Receive files with rncp* (Settings, Hosting; terminal only to turn on) makes rettui listen at your rncp address, as `rncp -l` does, and save files sent to *Received files folder* (`received/` by default). Only the identities in *Who may send files* may send; others are turned away and counted. A file is saved under its own name and never over another. Status shows the address and what has come in both UIs, and the web UI's *Send a file…* dialog lists the latest. See [Network](https://github.com/zevaryx/rettui/wiki/Network#receiving-files-with-rncp).
- **Get files from an rncp listener:** `O` in the Network tab, or **Get a file** in the web UI's **Send a file…** dialog, asks someone running `rncp -l -F` for a file by its path, as `rncp --fetch` does, and saves it in *Received files folder*. The listener must allow your identity. See [Network](https://github.com/zevaryx/rettui/wiki/Network).
- **Interfaces found:** `e` in the Network tab, or **Interfaces found** in the web UI, lists the entry points, RNodes and I2P addresses interface discovery finds, and those contacts send in their telemetry (Sideband 2.x's Interfaces sensor), as Sideband 2.x does: how to reach each, its radio settings, whether its node passes traffic on, and when it was heard. **Add to Reticulum** adds one to the Reticulum config (an entry point as a TCP client; an RNode off, until its port is set), and those that say where they are go on the map, marked ▲ (`i` on the map, or ▲ in the web UI, hides them). See [Network](https://github.com/zevaryx/rettui/wiki/Network).
- **Ask where someone is from the map, and what runs a propagation node:** `w` on the map (**📍 Ask where** in the web UI's map list) asks the person picked where they are now, as the contact card does. The announces list says what runs each propagation node (*lxmd 1.2.1*), as Sideband 2.x shows it. See [Messaging](https://github.com/zevaryx/rettui/wiki/Messaging#locations-and-the-map) and [Network](https://github.com/zevaryx/rettui/wiki/Network).
- **Identified visitors counted:** the Node tab (a Visitors line) and the web UI show how many different visitors who identified themselves to your node have come since it started A visitor who doesn't identify can't be told apart, so isn't counted, and the number starts again when the node does. See [Hosting a Node](https://github.com/zevaryx/rettui/wiki/Hosting-a-Node).
- **Python in the Docker image:** the image has Python 3, so script pages with `#!/usr/bin/env python3` run in it (when "Run page scripts" is on). See [Hosting a Node](https://github.com/zevaryx/rettui/wiki/Hosting-a-Node#script-pages).
- **Colours and art in rooms:** messages written in Micron, as NomadNet shows them in RRC rooms, are drawn in their colours, bold, italic and underlined, in both UIs. NomadNet writes the tags with `¦` (broken bar) where Micron has a backtick (`¦F0f0green¦f`), and only those are read, so other messages show as written. A message with colours isn't wrapped: pictures and lettering drawn in characters, sent a line a message (as art bots do), keep their shape, lined up under each other, and are cut off at the edge of the chat. See [RRC Chat](https://github.com/zevaryx/rettui/wiki/RRC-Chat).
- **Stopping a sync:** `S` again in the Status tab (**Stop sync** in the web UI) stops a propagation node sync that's running, after the download it's on, keeping what has come. See [Messaging](https://github.com/zevaryx/rettui/wiki/Messaging).

### Fixed
- **Reticulum 1.4:** rettui now runs rsReticulum 1.4 and rsLXMF 1.4. Among their fixes: a transport node you connect to gives your paths back after a reconnect without announcing again, a connectable I2P interface keeps its address across restarts, Reticulum's storage works on any filesystem (ZFS, Docker overlays, network shares), RNodes say which setting they refused rather than sending with others, and about one identity file in 29,000 that failed to load now loads. A message rettui sends keeps the exact bytes it signed. See [Settings and Reticulum Config](https://github.com/zevaryx/rettui/wiki/Settings-and-Reticulum-Config).
- **Interfaces start as in Python Reticulum:** an interface starts only when it says `enabled = Yes` (or `interface_enabled = Yes`). Before, one with neither started; now it's off, and rettui says so when Reticulum starts, on the Status page (where it's listed as off, in the TUI and the web UI), in its log and among the Reticulum config's warnings, so add `enabled = Yes` to keep one running. Interface profiles and the config editor show such an interface as off. See [Settings and Reticulum Config](https://github.com/zevaryx/rettui/wiki/Settings-and-Reticulum-Config).
- **Large messages aren't compressed for clients that can't take it:** a message too big for one packet is sent compressed, unless its recipient's announce lists what it takes and leaves compression out, as Python LXMF decides it. Before, rettui always compressed it. See [Messaging](https://github.com/zevaryx/rettui/wiki/Messaging).
- **Script pages that fail say so:** a script page that runs past its time limit, prints more than 512 KB or can't be run now sends the visitor a "Page failed" page. Before, nothing came back, and NomadNet showed "Request failed" after about 70 seconds. See [Hosting a Node](https://github.com/zevaryx/rettui/wiki/Hosting-a-Node).
- **Pages copied into the node's folder are served:** rettui looks for new pages and files in the node's folder every minute. Before, one copied in while rettui ran wasn't found until a restart or an edit in rettui. See [Hosting a Node](https://github.com/zevaryx/rettui/wiki/Hosting-a-Node).
- **Emoji and symbols in pages line up in the web UI:** an emoji, a CJK character or a symbol that the web UI's font doesn't have came from another font, which made its line a little longer or shorter than the lines around it, so boxes and bands drawn with text came out ragged. Each one now takes the same columns as in the terminal UI: two for emoji and CJK, one for the rest. See [NomadNet Browsing](https://github.com/zevaryx/rettui/wiki/NomadNet-Browsing).
- **The Android app's look:** with the web UI's light theme, the app kept dark strips above and below the page, under the phone's clock and buttons; they now take the page's colours, with the bars' icons dark on a light page, and the app remembers them for its next start. The app opens on rettui's dark background rather than a white flash on some phones, shows a spinner while rettui starts, and its own screens (Identity and backups, RNodes, Where files are saved) are dark on every phone, with their dialogs and buttons to match and their spacing the same on every screen size. If Android ends the page to free memory, the app loads it again rather than closing. See [Android](https://github.com/zevaryx/rettui/wiki/Android).

### Security
- **Hub nicks, leaves, idle links and the rooms file:** on your hub, nicks lose control and invisible characters, a nick someone else has (or the hub's own) isn't given, and the person is told; a leave for a room someone isn't in no longer tells the room they left; links that go quiet are pinged every 60 seconds and closed after 30 more (unless you set your own in the hub's `config.yaml`); and a rooms file cut off by a crash is put aside as `rooms.yaml.damaged` and the last good copy (`rooms.yaml.bak`, kept at each start) used, so the hub still starts. See [Hosting a Node](https://github.com/zevaryx/rettui/wiki/Hosting-a-Node).
- **Limits on what messages bring in:** received files and pictures can use at most 2000 MB in `downloads/` (*Received files limit*, `downloads_quota_mb`; 0 is no limit): one that would go over isn't saved, and the message is kept with a notice. Messages from a propagation node sync are now worked through 16 at a time instead of all at once. See [Data and Storage](https://github.com/zevaryx/rettui/wiki/Data-and-Storage).
- **Map tile sources set from the web UI:** a new source for map tiles must be an `https://` address on the public internet, so the web login can't make rettui ask this computer or its network for things. A source on a local network is set in the terminal UI, and one already set is kept. See [Messaging](https://github.com/zevaryx/rettui/wiki/Messaging#locations-and-the-map).
- **Ask before opening a file someone sent:** opening an attachment from a conversation (`o`, a click on it, or from the history) now asks first, because the program the system opens it with may do more than show it. Voice messages that play on arrival are not asked about. See [Using the TUI](https://github.com/zevaryx/rettui/wiki/Using-the-TUI).
- **Blocked contacts are turned away by what you host:** someone you've blocked is no longer answered by your node (once they identify), turned away from your hub, refused by your propagation node's message requests and offers, and refused by your git host. The git host reads the block list when it starts, so a change applies the next time it starts, and only for people rettui has heard announce. See [Hosting a Node](https://github.com/zevaryx/rettui/wiki/Hosting-a-Node).
- **Safer file names from others:** a file name sent with a message, a download or an upload is cut to its last part (whether it uses `/` or `\\`), loses control and direction-changing characters (which can make `txt.exe` read as `exe.txt`) and the characters Windows refuses, isn't saved hidden or as a Windows device name (`NUL`, `COM1`), and is at most 120 characters.
- **A failed web request no longer takes the web UI down:** if something a web request asks for panics inside rettui, that request fails and the web UI carries on.
- **Restoring a backup:** a backup that holds more than 4 GB or 200,000 files is refused, and restored files are private to you and can't be run as programs.
- **Limits on announces kept:** at most 100,000 destinations, and 4 KB of announce data for each, are kept from announces.
- **Limits on what a page makes the browser load:** a page or image bigger than 8 MB from a node is refused; a page loads at most 24 images and 16 partials, and a partial reloads no more often than every 5 seconds; and the page cache keeps no entry over 4 MB and drops the oldest entries past 128 MB in all. See [Browsing NomadNet](https://github.com/zevaryx/rettui/wiki/NomadNet-Browsing).
- **Hub rooms keep outsiders and the banned out:** on your hub, someone not in an invite-only, keyed or private room can no longer post to it, list who is in it or read its topic; only people in a room (or its operators) set its topic; and someone banned from a room is taken out of it on every connection they have, not only the newest. See [Hosting a Node](https://github.com/zevaryx/rettui/wiki/Hosting-a-Node).
- **Safer defaults for new setups:** a Reticulum config that rettui makes for you has *Share instance* off, so other programs on the machine can't use rettui's instance until you turn it on; *Auto-peer* for your propagation node is off, so it doesn't take on other nodes' load and storage unasked; and on a new hub only you make rooms (*Anyone makes rooms* is off). Settings and configs you already have are not changed. See [Network](https://github.com/zevaryx/rettui/wiki/Network) and [Hosting a Node](https://github.com/zevaryx/rettui/wiki/Hosting-a-Node).
- **SQLite 3.54:** the SQLite library that stores games and chats read uninitialised memory when a crafted database and `-wal` file were opened together ([RUSTSEC-2026-0459](https://rustsec.org/advisories/RUSTSEC-2026-0459)). rettui only opens files it wrote itself, so it wasn't affected, but it now uses the fixed version.
- **pulldown-cmark 0.13.6:** pulldown-cmark, which reads Markdown in messages, could take quadratic time on nested image wiki-style links ([RUSTSEC-2026-0433](https://rustsec.org/advisories/RUSTSEC-2026-0433)). rettui doesn't turn on wiki-style links, so it wasn't affected, but it now uses the fixed version.
- **Keys wiped from memory:** with Reticulum 1.4, keys worked out to decrypt, interface passphrases and I2P keys are wiped from memory once they're no longer needed, and an identity file over 1 KB is refused rather than read. See [Data and Storage](https://github.com/zevaryx/rettui/wiki/Data-and-Storage).
- **A script page's text is no longer sent when scripts are off:** with "Run page scripts" off, a visitor who asked for an executable page was sent the script's own text, which could hold secrets. They now get the same "not found" page as for a page that isn't there. See [Hosting a Node](https://github.com/zevaryx/rettui/wiki/Hosting-a-Node#script-pages).
- **The identity stays off a new Android phone set up from yours:** Android 12 and later copy apps' files to a new phone set up from an old one, even from apps that turn backups off, so the identity went with them, and both phones then answered for the same address. The app now leaves all of its data out of that transfer, and out of cloud backups. The identity moves only when you save it from *Identity and backups*. See [Android](https://github.com/zevaryx/rettui/wiki/Android#identity-and-backups).
- **A hub you host can't be taken down by a crafted message:** the check that keeps `/ban` and `/invite` for rooms that don't exist away from the hub's code read a message differently from the hub, so a message with a key given twice, or under a CBOR tag, got past it and stopped the hub, leaving its panel saying it was still running. The check now refuses any message the hub could read differently, and the panel says when the hub's task stopped. See [RRC Chat](https://github.com/zevaryx/rettui/wiki/RRC-Chat).
- **Game moves with a wide character can't crash rettui:** a Quoridor wall or Battleship fleet ending in a character wider than one byte, sent as a game move by anyone, made rettui panic. It's now refused as not a legal move, and a game message that makes the game engine fail costs only that message.
- **Voice messages can't crash the decoder:** a 450 or 450PWB voice message with an index past the end of its table made the decoder panic. The index is now held to the table.
- **Only listed senders' files are kept by the rncp listener:** the listener saved a file from a sender who never said who they were, whatever the allowed list said, and a file name ending in `..` put the file beside the folder. rettui now deletes both and counts them as refused. See [Network](https://github.com/zevaryx/rettui/wiki/Network).
- **A background thread's panic leaves the terminal alone:** a panic in a worker thread (a voice decode, a message being read) used to take the terminal out of raw mode and off the alternate screen while rettui kept running. Only a panic in the UI itself does that now; the others go to the log.
- **Copies of a restricted page are no longer served:** a node served `secret.mu~`, `secret.mu.bak` and `secret.mu.allowed~` (what editors leave behind) with no `.allowed` list of their own, which showed the page, or who may see it, to everyone. A name that ends in `~`, `.bak`, `.orig`, `.old`, `.tmp`, `.swp`, `.save` or `.rej`, that is wrapped in `#`, or that has `.allowed` in it in any case, is no longer served or accepted as a name. See [Hosting a Node](https://github.com/zevaryx/rettui/wiki/Hosting-a-Node).
- **A page whose `.allowed` is a folder or pipe is closed, not open:** the node treated such a list as no list and served the page to everyone. It now lets no one in, and the Node tab says the list isn't a file.
- **Allow lists are written under a hidden name:** saving who may see a page wrote `club.mu.tmp` beside it, which the node could serve, before putting it in place. Every file rettui saves now goes through `.name.tmp`. A rename that can't move a page's list puts the page back, not open to everyone.
- **What rettui keeps is private to you:** the data folder is closed to other users on the machine (mode 700), and the message store, contacts and known keys, settings and the log are written readable by you alone. A new identity file is made private from the start, not after it was written. See [Data and Storage](https://github.com/zevaryx/rettui/wiki/Data-and-Storage).
- **A message from someone whose key isn't known yet can't act for them:** a message that claims to be from a contact but whose signature couldn't be checked (their key wasn't known) is still shown, marked unverified, but no longer makes rettui answer commands or location requests, take map positions from it, or change their icon. It says "Not acted on" in the message.
- **Checking a stamp no longer holds up other messages:** with a stamp cost set, working out each message's stamp held the message settings that the link manager also needs, so a flood of stamped messages stalled files arriving. It is now done a few at a time, with the settings free.
- **The web UI refuses requests from other pages:** the login cookie is kept from other sites, but a page on another port of the same machine counts as the same site, so it could make your browser quit rettui, switch identity, start an update or send a file. Requests that change something are now refused unless the browser says they come from the web UI itself (`Sec-Fetch-Site`, or `Origin` matching `Host`). Scripts and tools that send neither header are not affected. See [Web UI](https://github.com/zevaryx/rettui/wiki/Web-UI).
- **A message can't make rettui allocate gigabytes:** a Markdown message with a quote or list nested thousands deep took memory in proportion to depth times length when drawn in the terminal, and could crash rettui each time the conversation was opened. Nesting is drawn at most 8 deep.
- **A stamp cost nobody can work out is refused:** a recipient or propagation node can announce any stamp cost up to 255, and working out one above 28 would keep a thread busy for good. Sending to them now says the cost is more than rettui will work out.
- **Text from a room member can't pose as the hub:** a notice a hub passed on as a Resource (text over 300 bytes) was shown as the hub's own whoever sent it, and could change topics, the room list and who is in a room. Only a notice from the hub itself is taken as one now.
- **Blocking covers rooms and whispers:** a blocked person's messages in an RRC room, and their whispers, are no longer shown.

### Docs and development
- **Android and AutoInterface:** the [Android](https://github.com/zevaryx/rettui/wiki/Android) page no longer says AutoInterface finds no peers. On a phone it binds its ports, joins the Wi-Fi multicast group and finds a desktop on the same network. It was off in the config that was tested, and a desktop firewall that blocks UDP ports 29716 and 42671 keeps peers from hearing each other.
- **Reticulum License:** rettui is now under the [Reticulum License](https://github.com/zevaryx/rettui/blob/main/LICENSE), the license of Reticulum, LXMF and, from 1.4, rsReticulum and rsLXMF, rather than the AGPL-3.0-or-later. It allows using, changing and passing on rettui, except in systems built to harm people and in making or training AI or machine-learning models. Release archives, packages and the Docker image now carry the license file. rettui no longer includes rsNomad, which is AGPL-3.0-or-later (see below).
- **rsReticulum 1.4:** `deps/rsReticulum` is zevaryx's fork at rsReticulum 1.4.0 (branch `rettui-1.4`), with its NomadNet file replies and the identity of who sent a request carried forward; `deps/rsLXMF` is at 1.4.0, and `deps/rngit-rs` takes the same rsReticulum commit.
- **rngit-rs:** `deps/rngit-rs` reads one commit with the files it changed, pages through history, and lists what one visitor may read, for the pages above.
- **A NomadNet node of rettui's own:** rettui no longer builds on rsNomad, and `deps/rsNomad` is gone: hosting a node, and asking other nodes for pages, files and pictures, is now rettui's own code (`src/nomad/`), written from NomadNet's formats. A hosted node works as before: pages, files, `.allowed` lists, script pages with their `PATH` and time limit, pictures sent as WebP and visitor counts. One small difference: a script page that fails is answered with "Page failed … could not be made on this node". See [Hosting a Node](https://github.com/zevaryx/rettui/wiki/Hosting-a-Node).

## v1.10.0

Changes since v1.9.0: git repositories on rngit nodes (their branches, releases and work documents, and a copy of one kept on your computer) in a new Repos tab, hosting repositories for others to clone and push to over Reticulum, and mirroring, forking and managing them and who may use them from the Repos tab, nine more games (Ultimate Tic-Tac-Toe, Go, Battleship, Quoridor, Nine Men's Morris, Breakthrough, Amazons, Pente and Rock Paper Scissors), a first version of an Android app, attached to the release, the web UI reworked for phones, how to play each game beside its board, copying an identity, or keeping another, from the command line, development prereleases of `dev` on command, the web UI's questions in dialogs of its own, tabs in the Browser, your own node's script pages run in the Browser, Sideband commands sent, how a send or sync is going and cancelling a send, your location sent on a timer and someone tracked, telemetry collectors, the propagation node you host passing messages on to other nodes, interface profiles to switch between, Reticulum's path table and announce rates, trails of where people have been on the map, pages kept to those you pick, files uploaded to your node without a page, what your node has served, files sent to rncp listeners, speed tests with rettui or NomadNet, whose an address is, what an RNode's settings come to, voice messages played as they come, LXMF comments and continuations shown for what they are, places passed on to an MQTT server, paper messages printed from the terminal, what others send (messages, pages, pictures, RRC notices, entry points) kept from losing your saved messages, stopping or holding up rettui, using up its memory or passing for an RRC hub, the web UI kept from starting a pipe interface's program, and less battery, disk and network used (most of all on Android).

### Added
- **Choose where Android saves files:** *Where files are saved* (Status, in the app) picks a folder with Android's own folder picker, or asks each time with its *Save as* screen, for NomadNet files, exports and backups. It needs no storage permission. See [Android](https://github.com/zevaryx/rettui/wiki/Android).
- **Repos tab:** read and write git repositories hosted on [rngit](https://github.com/zevaryx/rngit-rs) nodes, in both UIs (`0` in the terminal). Add one by its `rns://` URL, or open an `rns://` link in a message or page; rngit nodes that announce are listed too. Each shows its branches and tags, its releases (whose files download checked against the release's signature), its work documents with their comments (and whether the author's signature checks out), and its permissions. If the node lets you, you can write, propose, comment on, edit, finish and delete documents, and publish and delete releases. *Use rngit's identity* (terminal only) asks as the `rngit` command's identity, and *rngit timeout* sets how long a request may take. `m` (**Copy to this computer** in the web UI) keeps a copy of a repository with all its branches and tags in rettui's data folder, to read or clone from, and brings it up to date later, removing what the node no longer has; `M` deletes it; `u` (**Send to…**) sends the copy, with all its branches and tags, to another repository, which is made there if it isn't, leaving branches that differ unless you choose to overwrite them (and to delete what the copy lacks). The copy can be read without the node: `Enter` on a branch or tag looks at its files, a file's text and its newest commits, and if the node doesn't answer the copy's branches and tags show instead. An rngit node picked in the list opens its pages in the Browser (`n` on it adds a repository there): most nodes serve their pages from another identity, so it asks once which NomadNet node has them (guessing by name) and remembers the choice (`b`, or ⌂ in the web UI, to change it), and `a` in the Browser (**Keep repos**) keeps every repository a page links to. ### Security
- **pulldown-cmark 0.13.5 and crypto-bigint 0.7.10:** pulldown-cmark, which reads Markdown in messages, had a flaw ([RUSTSEC-2026-0414](https://rustsec.org/advisories/RUSTSEC-2026-0414)) where a crafted wiki-style link could make it do exponentially more work. rettui doesn't turn on wiki-style links, so it wasn't affected, but it now uses the fixed version. crypto-bigint 0.7.7, used for P-256 signatures, had been withdrawn by its authors and is replaced by 0.7.10.
- **A message's time can no longer lose your messages:** a message whose time wasn't a number (which anyone can send) was saved in a way rettui couldn't read back, so at the next start every conversation was gone, and the next save wrote over them. A time that can't be one (not a number, before 1970 or after 9999) is now taken as when the message came; a saved time like that reads again; and a store that can't be read is moved aside rather than saved over. See [Data and Storage](https://github.com/zevaryx/rettui/wiki/Data-and-Storage).
- **A message's time can no longer stop the terminal UI:** a message dated near the end of the times rettui can hold (the year 262142) stopped rettui whenever it was shown, in time zones ahead of UTC (near the start of them, behind UTC), and again each time its conversation was opened. An RRC chat line could do the same. Such a time now shows none, and a new message's is taken as when it came. See [Messaging](https://github.com/zevaryx/rettui/wiki/Messaging).
- **Long Micron messages and pages no longer hold rettui up:** some Micron markup (many images, anchors or form fields on a page, or in a message, which can be a megabyte) was read again for each one, so a message of it took minutes to show. The terminal UI read it again each time it drew the conversation, and the web UI each time it fetched it, holding up the web UI for everyone. Micron is now read in one pass, and a formatted message (Micron or Markdown) is kept once it's made. See [Messaging](https://github.com/zevaryx/rettui/wiki/Messaging).
- **A page of dividers can no longer swamp the web UI:** each Micron divider (two characters of a page) was drawn in the web UI as 1200 of its character, so a page or message of them made gigabytes, which held up the web UI for everyone and could run the computer out of memory. A page's first 50 dividers are drawn as before and the rest as a plain line. See [NomadNet Browsing](https://github.com/zevaryx/rettui/wiki/NomadNet-Browsing).
- **Others in an RRC room can no longer pass for the hub:** a notice another user sent to a room was taken as the hub's, so it showed as `-hub-` and could change the room's topic, the list of rooms or who's there, or open a stretch of "history" whose messages then showed any time their sender chose. Only the hub's own notices do that now; another user's shows as said by them. See [RRC Chat](https://github.com/zevaryx/rettui/wiki/RRC-Chat).
- **A discovered entry point can no longer be this computer:** an entry point anyone announces was connected to unless its address was written exactly as `127.0.0.1`, `::1` or the like, so one given as `127.1.2.3`, `localhost` or `::ffff:127.0.0.1` had rettui connect to whatever listens on this computer. Addresses are now read as addresses, and none of this computer's is used. Entry points elsewhere on your network still are. See [Running](https://github.com/zevaryx/rettui/wiki/Running).
- **One message can no longer have rettui send thousands:** with *Answer commands* on, every command in a message was answered with a message of its own, and an echo was sent back however long it was, so one message could have rettui send thousands, each a megabyte. Only a message's first 8 commands are read now, and an echo's first 500 characters sent back. See [Messaging](https://github.com/zevaryx/rettui/wiki/Messaging).
- **The web UI can no longer start a pipe interface's program:** it couldn't add or change a pipe interface's command, but it could turn on one that was off, or copy one, which runs its program when Reticulum starts. That's now kept to the terminal too; turning one off still works from the web UI. See [Settings and Reticulum Config](https://github.com/zevaryx/rettui/wiki/Settings-and-Reticulum-Config).
- **Pictures can no longer run the terminal UI out of memory:** a picture of a few kilobytes can say it's millions of pixels across, and was decoded however large it said it was, each on a thread of its own, so a page or conversation of them could take gigabytes. A picture wider or taller than 16384 pixels isn't shown now, one decode takes at most 256 MB, and pictures are decoded two at a time. See [NomadNet Browsing](https://github.com/zevaryx/rettui/wiki/NomadNet-Browsing).

- **Claim a draw** in Chess and Checkers (`C` in the terminal, a button in the web UI): offered when the same position has come up three times, or after fifty moves (Chess) or forty (Checkers) without a capture or a pawn or man moving. The game ends at once; the other side checks the claim.

- **Reactions from Mesh-Client:** a reaction from [Mesh-Client](https://github.com/Colorado-Mesh/mesh-client) no longer shows as a message as well as on the message it's for. ([#31](https://github.com/zevaryx/rettui/issues/31))
- **Stopping the web UI right after it starts:** a stop (Ctrl-C or SIGTERM) sent while `rettui --web` was still starting up could end it abruptly instead of shutting it down cleanly; the signals are now listened for before the link is printed.

- **Drafts stay with their conversation:** opening a conversation from a link or a notification while writing in another no longer carries the half-written message over to the one being opened.

Those intermediates' private keys are known publicly.

- The code is formatted with rustfmt, and CI checks it.
- A release's notes are its section of this changelog; tagging fails without one.

### Known limitations
- Messages received over a Link (most direct messages) don't show RSSI/SNR: rsReticulum doesn't say how a Link's packets were heard.
- LXST voice calls aren't supported because of LXST's license (CC BY-NC-ND 4.0).
